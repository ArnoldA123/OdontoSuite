## 1. Resumen

CRUD admin de métodos de pago (`/settings/payment-methods`) + columnas `gateway_type`/`gateway_config` para preparar la integración con Mercado Pago (Sprint 3). Incluye:
- Endpoint público `/payment-methods/active` para dropdowns de cobro (todos los autenticados)
- Endpoint admin CRUD protegido por `role:administrador`
- Encriptación de credenciales de pasarela con `Crypt::encryptString`
- Validaciones: métodos del sistema no se borran, métodos con transacciones no se eliminan

## 6. Decisiones técnicas

### 6.1 Endpoint `/payment-methods/active` público

Mismo patrón que `/branches/active` (Sprint 1, Pattern L del skill): la ruta con segmento fijo `/active` se registra en el grupo público (sin role middleware) **antes** del `apiResource` que está en el grupo `role:administrador`. Esto permite que recepcionistas y finanzas puedan listar métodos para el dropdown de cobro sin necesitar permisos de admin.

### 6.2 `gateway_config` como `text` en vez de `json`

La migration original lo definía como `json` (column type MySQL). Pero `Crypt::encryptString()` produce un string base64 estándar (no JSON), y MySQL JSON columns rechazan strings no-JSON con error 3140. La migration `140001` cambia la columna a `text` para resolver esto.

### 6.3 Encriptación en accessors del modelo (no en el controller)

La lógica de encrypt/decrypt vive en `PaymentMethod::setGatewayConfigAttribute()` y `getGatewayConfigAttribute()`. Esto es transversal: cualquier `create()` o `update()` que incluya `gateway_config` pasa por el accessor automáticamente. El controller nunca llama a `Crypt` directamente. Patrón estándar de Eloquent mutators.

### 6.4 `makeHidden('gateway_config')` en respuestas API

Los accesos a payment methods vía API nunca devuelven el secret encriptado. Solo el campo booleano `has_gateway_config` (true/false) se expone. Esto evita que un atacante con token de recepcionista obtenga credenciales de Mercado Pago de la BD.

### 6.5 `is_system` como protección contra borrado

El controller (`destroy`) verifica `is_system` antes de ejecutar `delete()`. Si es `true`, devuelve 403. Esto protege los 5 métodos seedeados (cash, transfer, credit_card, debit_card, yape) contra borrado accidental por el admin. El admin puede desactivarlos (`is_active=false`) pero no eliminarlos.

### 6.6 `PaymentMethodFormModal` maneja `isSystem` = fields deshabilitados

Cuando el admin abre el form de editar un método del sistema, todos los campos están `:disabled` y el footer muestra "Método del sistema" en vez de "Actualizar". Esto es intencional: los métodos del sistema se seedearon con comisiones y configuración estándar, el admin solo puede desactivarlos.

## 8. Deuda técnica

1. **`doctrine/dbal` no instalado**: la migration `140001` usa `DB::statement` MySQL-specific en vez de `Schema::change()`. Funciona pero no es portable a SQLite. Documentado como `Pattern S` del skill.
2. **Gateway config no se puede editar parcial**: si el admin actualiza solo el `public_key` sin mandar `access_token`, se pierde el valor anterior (se pone null). Esto se resuelve en Sprint 3 con un endpoint dedicado `PUT /payment-methods/{id}/credentials`.
3. **No hay test de encriptación**: el accessor `setGatewayConfigAttribute` encripta, `getGatewayConfigAttribute` desencripta, pero no hay test PHPUnit que verifique roundtrip. Agregar en Sprint 3.
4. **Las credenciales MP (public_key, access_token) no se muestran nunca al admin**: solo `has_gateway_config` se expone. El admin tiene que re-ingresarlas si quiere cambiar algo. Esto es intencional (seguridad), pero la UX podría mejorar con un botón "Reconfigurar pasarela" que permita escribir nuevos valores sin mostrar los viejos.
